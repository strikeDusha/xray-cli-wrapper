# Архитектура v3xtun

## Обзор

v3xtun — десктопное приложение на **Tauri 2**. Фронтенд (HTML/TS/CSS, бандлится Vite)
рисует интерфейс и через `invoke()` зовёт Rust-команды; Rust управляет дочерними
процессами **xray** и **tun2proxy** и хранит конфигурацию.

```
┌─────────────────────────────┐   invoke()    ┌───────────────────────────────┐
│  Webview (TypeScript)        │ ────────────▶ │  Rust (Tauri core)            │
│  index.html / src/main.ts    │ ◀──────────── │  commands.rs                  │
│  вкладки, кнопки, логи        │  events:      │   ├─ process.rs (xray/t2p)    │
└─────────────────────────────┘  status/log    │   ├─ config.rs  (настройки)   │
                                                │   └─ tray.rs    (трей)        │
                                                └───────────────────────────────┘
```

## Поток трафика

```
приложения ОС
   │
   ▼ маршрут по умолчанию
TUN-интерфейс (tun0)  ←—— создаёт tun2proxy
   │
   ▼ --proxy socks5://127.0.0.1:10808
xray, inbound SOCKS5
   │
   ▼ outbound (vless/vmess/trojan/ss)
ваш сервер
```

`xray` отвечает за протоколы и проксирование; `tun2proxy` — за перехват всего
системного трафика на уровне ядра через TUN.

## Процессы (process.rs)

- Каждый процесс хранится в `Mutex<Option<Child>>` внутри `AppState`.
- stdout/stderr читаются отдельными потоками, строки кладутся в кольцевой буфер
  (до 2000 строк) и эмитятся во фронтенд событием `log`.
- Фоновый поток-монитор раз в секунду проверяет `try_wait()` и при изменении
  состояния шлёт событие `status`.
- **Остановка — graceful:** сначала `SIGTERM` (через `libc::kill`), ожидание до 3 с,
  и только потом `SIGKILL`. Это критично: по `SIGTERM` tun2proxy (`--setup`)
  восстанавливает маршруты и DNS; `SIGKILL` оставил бы систему без сети.
- При выходе приложения (`RunEvent::ExitRequested`) и через пункт трея «Выход»
  вызывается `stop_all`, чтобы туннель гарантированно снялся.

## Сборка команд (config.rs)

- `xray`:  `xray run -c ~/.config/dev.v3xtun.app/xray-config.json`
- `tun2proxy`:
  `tun2proxy-bin --proxy <URL> --tun <name> --setup --dns <mode> [--dns-addr <ip>] [--bypass <ip>]… [--ipv6]`
- Записи bypass (IP/CIDR/хостнеймы) перед стартом приводятся к IP: хостнеймы
  резолвятся через `ToSocketAddrs`. Это закрывает петлю маршрутизации, когда
  собственное соединение xray к серверу иначе ушло бы обратно в TUN.

## Права

tun2proxy требует `CAP_NET_ADMIN`. Основной путь — разовый
`setcap cap_net_admin,cap_net_raw+ep` на бинарь через `pkexec` (кнопка «Выдать права»),
после чего рантайм работает без root и остановка по сигналу надёжна. Фолбэк —
запуск через `pkexec` при каждом старте (`use_pkexec`), но тогда корректное снятие
root-процесса по сигналу не гарантируется.

## Хранилище

`~/.config/dev.v3xtun.app/`
- `settings.json` — пути к бинарям, параметры tun2proxy, флаги (автозапуск, трей, автоконнект).
- `xray-config.json` — конфиг xray (редактируется в GUI, валидируется как JSON перед записью).

Автозапуск реализован нативно для KDE/freedesktop — `~/.config/autostart/v3xtun.desktop`.

## Известные ограничения

- TUN-режим здесь проще, чем полноценный fail-closed kill-switch: при падении
  tun2proxy возможна кратковременная утечка до перезапуска. Защиту (split-default
  маршруты `0.0.0.0/1`+`128.0.0.0/1`, blackhole IPv6, фиксацию DNS) можно добавить
  по образцу — это следующий шаг развития.
- Rust-часть собирается под Linux (webkit2gtk); проверка сборки делается на целевой
  Arch-машине.
